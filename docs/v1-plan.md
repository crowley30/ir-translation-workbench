# V1 范围与实施计划

## 使用者与目标

本工具面向人民币与美元科技基金的 IR，重点行业为 AI 和具身智能，用于将英文 DOCX 或粘贴邮件整理成便于复核的中文材料。V1 的重点是可追溯的原译对照、人工编辑保护和明确的内容完整性提示。工具提供翻译辅助，最终材料由使用者复核。

P0/P1 mock 文本工作闭环已经父任务接受，基线为 `22909dca`。当前 P2 将 DOCX 导入预检查与中文/双语基础导出合并交付，以 [P2 任务书](p2-plan.md) 和 [P2 执行记录](p2-verification.md) 为准；术语、数值检查与解释仍为后续阶段。忽略旧的、未经测试的一句话 Codex skill。

## 技术架构

| 层        | 选择                                             | 理由与边界                                                                 |
| --------- | ------------------------------------------------ | -------------------------------------------------------------------------- |
| 界面      | React + TypeScript + Vite                        | 中文、桌面优先；输入、任务列表、逐段对照、编辑与运行状态保持在一个工作台中 |
| HTTP 服务 | Node.js 24 + Express + TypeScript                | 单进程便于维护；前后端共享类型；只在本机监听                               |
| 存储      | Node 内建 SQLite，文件置于 `.data/`              | 不引入外部数据库服务；任务与段落状态增量保存；数据库不纳入 Git             |
| 翻译服务  | 服务端适配层，mock 与 real 明确区分              | 默认 mock；凭据不进入浏览器；没有真实配置时不伪装实际翻译                  |
| 验证      | ESLint、TypeScript、Vitest/Supertest、Playwright | 分别检查静态质量、服务与存储行为、用户浏览器流程                           |

任务包含固定 ID、文体、模型模式、运行状态、时间戳和段落列表。段落包含固定 ID、原文、译文、版本号、人工编辑标记和运行状态。翻译结果回写前比较版本号，阻止较早的异步结果覆盖较新的人工编辑。任务运行时阻止重复提交，取消和故障状态均持久化，刷新与导航后可重新查询。

创建请求等待期间锁定原文和选项并使用提交快照；失败保留原文。若服务模式变化，保留原文草稿及已创建任务，停止自动翻译。

当前以空行划分文本段落，不假设每个换行都是段落。字符与段落数限制同时由服务端校验。原文保存后不在原任务中改写，以维持稳定段落映射；更换原文应创建新任务。

局部重译必须指定段落 ID。未指定范围的运行仅处理尚未完成且未人工编辑的段落；明确选择人工编辑段落进行重译意味着替换该段已保存译文，但运行开始后的人工修改仍应受到版本检查保护。其它段落不受影响。

## 模式、故障与保密

模拟模式用于流程验证，输出必须带有「模拟占位、非译文」标记，并在页面、任务和导出中保持可辨认。模拟不能评价语言准确性、合同忠实度或行业术语质量。

真实服务适配器只接受服务端配置，需显式启用；缺少必要配置必须明确报告不可用。真实调用的接入验收放在获准使用测试预算和服务后进行，本轮不得发出收费 API 请求。配置细节见 `.env.example`。

| 服务端变量               | 默认值 / 作用                             |
| ------------------------ | ----------------------------------------- |
| `DATABASE_PATH`          | `.data/workbench.sqlite`，SQLite 文件路径 |
| `PORT`                   | `3001`，仅绑定 `127.0.0.1`                |
| `APP_ORIGIN`             | 可选，额外允许的明确本地 Origin           |
| `TRANSLATION_MODE`       | `mock`；显式设为 `real` 才考虑真实服务    |
| `TRANSLATION_TIMEOUT_MS` | `3000` 毫秒，限制在 100–30,000 毫秒       |
| `ALLOW_REAL_TRANSLATION` | 必须为 `true` 才能启用真实请求            |
| `TRANSLATION_API_KEY`    | 只在服务端读取，禁止提交或展示            |
| `TRANSLATION_MODEL`      | 真实服务模型名称                          |
| `TRANSLATION_API_URL`    | 真实服务的 HTTPS 接口地址                 |

本轮没有设置真实服务变量，也没有用真实服务执行验收。

适配层对超时、429、5xx、部分失败和格式错误给出可理解的分类。每段最多尝试 3 次，重试退避为 120 / 240 毫秒；取消应中止在途请求与后续重试。只有完整的受支持成功完成状态可保存为译文：真实适配器要求 `finish_reason=stop`、单个 assistant 输出且无拒绝或工具调用；截断、拒绝、缺失/未知状态不会标为成功。成功段落增量保留，失败段落可单独重试。服务重启将中断的运行标为已取消并给出说明，不自动续跑或产生费用。不得把服务商原始响应、凭据或输入全文写入日志与错误信息。

应用仅适用于可信本机单人环境；无登录、无远程权限管理、无应用级数据库加密。不得部署到公网。数据库、用户导出、原始浏览器报告和临时产物均不提交。`docs/evidence/` 中仅保留经检查的合成样本截图及脱敏检查记录。提交前检查凭据、真实用户数据与临时产物。

## 分阶段任务

| 阶段                   | 交付物                                                                                                             | 验收出口                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| P0：本轮基础           | 仓库规范检查、架构、V1 边界、运行文档、验收矩阵；中文界面与服务端 SQLite 数据模型；诚实 mock                       | 可从干净安装启动；模式清楚；无真实凭据、付费调用或真实样本                       |
| P1：本轮文本闭环       | 文本校验、双文体、逐段对照、编辑保存、任务列表与重新打开、复制与文本导出、局部重译；重复请求、取消、重试与状态恢复 | 本轮验收矩阵逐项执行，记录命令、退出码与证据；未运行明确注明                     |
| P2：DOCX 导入          | 正文、标题、列表、简单表格解析；预检查报告；稳定段落和结构映射                                                     | 合成 DOCX 覆盖各支持结构；unsupported 内容明确列出并阻止误以为完整，绝不静默遗漏 |
| P3：DOCX 导出          | 中文和双语 DOCX；保留支持范围内的标题、列表、简单表格关系                                                          | 导出重新解析与人工打开检查；原文段落覆盖与顺序一致；unsupported 不伪装完整       |
| P4：术语与辅助检查     | 项目、基金、技术三层术语；数字、币种、日期检查；辅助解释                                                           | 术语来源与覆盖规则可见；检查可定位到具体原译段落；解释与译文清楚分隔             |
| P5：真实服务及质量验收 | 在另行授权和配置后，以受控测试集接入真实模型                                                                       | 独立记录请求成本、真实适配器兼容性和专业人工评审；不以 mock 通过替代             |

## 后续 V1 设计约束

DOCX 导入前先生成内容清单与预检查：支持的正文、标题、列表、简单表格，以及发现的图片、嵌入对象、批注、修订、脚注尾注、文本框、复杂表格等内容。对于不支持的类型，显示数量、位置和影响；要求使用者解决或明确处理策略，不能默默丢掉后继续显示「导入成功」。解析与导出共享稳定结构 ID，保留来源位置和段落映射。

三层术语建议按「项目 > 基金 > 技术」匹配，先给出适用范围、冲突和命中预览，再应用到翻译请求。编辑术语不自动改写已确认的人工译文，需由使用者选段重译或调整。实际规则在 P4 验收前确认。

数字、币种和日期检查提供可定位提示，覆盖金额、百分比、倍数、区间与常见中英文日期；检查仅提示差异，不擅自修改译文。辅助解释独立显示并标记为模型建议，不混入最终译文或合同正文。

## 明确不做

V1 暂不做 PDF、OCR、邮件系统接入、自动发送、多人协作、公开部署或复杂知识库。仓库可以公开，但应用保持本机单人模式。不合并 `main`，不发布 release，不部署；本轮完成后提交分支、push 并尝试创建 draft PR，交由父任务验收安排下一轮。
