# P3：术语快照与确定性复核计划

## 基线与阶段合同

本轮起点为父任务已接受的有限 P2 mock 基线 `127d499`。已接受范围是文本闭环及有边界的 DOCX 预检查、结构映射与基础中文/双语导出；不代表 Microsoft Word 人工打开、真实 API 或专业翻译质量通过。这三个原有门禁继续保留。

P3 只增加用户维护的三层术语、任务级不可变快照、显式重新应用，以及确定性复核提示和用户复核记录。实现以 `shared/professional.ts` 为共享合同；本计划与 [验收矩阵](p3-acceptance.md) 在本轮实现完成前写入，新增检查在实际执行前均为待运行。规则细节由 [复核规则说明](p3-review-rules.md) 记录；合成评估与真实质量空表见 [评估计划](p3-evaluation.md)。

继续只用合成内容、默认 mock，不配置真实凭据、不调用收费服务、不访问或修改 PowerQuery、不合并 main、不发布或部署。不增加知识库、邮件接入、多人协作或后台自动审签。

用户在本轮追加离线自定义 API 接口：保存 provider 协议类型、基础地址、模型与服务端凭据引用，区分配置状态；不接 API、不测试连接、不保存真实密钥。生产默认真实 transport 保持关闭，旧环境开关不能激活；注入 stub 仅用于离线契约测试。静态 URL 校验和未来 DNS/连接目标安全门禁详见 [服务设置契约](p3-provider-settings.md)。此追加项属于 P3，实际检查另行记录。

## 有界数据合同

| 对象             | 本轮内容与约束                                                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 术语记录         | `project/fund/technical` 层；项目名、源词、目标译法或保留原词、备注、0–100 整数优先级、启用状态、大小写敏感开关、可接受替代译法；固定 ID、版本与时间戳 |
| 术语库           | 库版本和记录列表；新增/编辑/停用需校验输入与版本冲突；用户输入，不是权威行业词典                                                                       |
| 任务快照         | 固定 ID、创建时间、库版本、项目与上下文、记录副本；创建后不可编辑，术语库变化不反向修改旧任务                                                          |
| 重新应用预览     | 预览 token、任务版本、旧快照 ID、候选快照、变化源词、冲突与位置、保留人工编辑数量                                                                      |
| 复核状态         | 可定位提示、用户确认、确认/撤销/失效事件；确认绑定段落版本与快照 ID                                                                                    |
| 服务端翻译上下文 | 当前项目、上下文、快照 ID、相关术语、段落位置和相邻原文；通过适配层传入，不进入公开日志                                                                |

按共享常量限制：最多 200 条术语；源词 80 字符、目标 160 字符、项目名 80 字符、上下文 2,000 字符、备注 400 字符，每词最多 8 个替代译法；任务最多保存 20 个历史快照。历史满额时拒绝继续重新应用，不静默删除旧快照或覆盖历史。字段边界同时在服务端校验，空值、矛盾状态和超限需给出清楚错误。

每段术语匹配最多 1,000 个不同位置、10,000 个候选，超限明确报错而不截断为成功；每段最多显示 80 项常规复核提示并附完整人工核对提示。复核事件只保留最近 100 条，当前有效确认独立保存，不因事件裁切丢失；此限额与不可丢弃的旧术语快照分开。

目标译法与保留原词是明确的用户选择；不能用空目标冒充完成配置。三条一次性初始化的通用示例默认禁用并标明「示例、非权威」，不自动应用，也不从人工译文中自动学习或晋升术语。

## 术语选择与应用边界

仅启用记录参与匹配；项目层只适用于选定项目，当前项目候选优先于基金/技术全局候选；同范围按显式数值优先级比较。同一位置最高优先级仍冲突时列出候选、层和位置，不替用户代选目标。基金与技术层的区别是来源范围，不暗设其一永远高于另一层。大小写和替代译法按记录配置处理，匹配与重叠规则需有可重复的测试与规则说明。

创建任务时保存术语/项目/上下文快照。之后修改术语库只影响新预览；旧快照及旧任务历史不变。现有任务采用新规则必须先预览，再由用户明确确认，并以预览 token、旧快照和任务版本执行 CAS；预览后任务、库或相关输入改变时拒绝陈旧确认并要求重新预览。

重新应用只替换任务的术语/上下文快照并更新复核状态，**保留所有已有原文、译文、人工编辑标记与结构映射**。它不会自动翻译，也不会批量替换现有译文；需要改译时仍由用户选择具体段落，沿用已验收的版本保护。重新应用使旧快照下的复核确认失效并留事件，不能让旧确认看似审核了新规则。

## 确定性复核与人工确认

本轮提供空译文、数字、币种、日期、比率、明显遗漏、术语不符/冲突、格式不确定和 mock 输出提示。每项含段落 ID/位置、源文与译文的可用字符范围、代码、可理解的原因和确定性标记；不存在的对应范围为 `null`，不伪造定位。

这些规则只能发现有限模式，不判断专业准确性，不做汇率换算、投资建议、法律审签或语义完整性证明。无法确定的格式应标不确定并交由用户复核；明显遗漏也只是启发式提示。规则不能自动改稿、自动确认、自动发送或把「无提示」写成「译文正确」。mock 输出必须始终标明非真实译文，不能给专业质量分。

复核确认只能由用户动作产生，绑定当前段落版本和快照 ID。改译、保存新版本、重译或显式重新应用改变依据后，相应确认失效；陈旧确认请求被拒绝。状态与事件随任务保存、刷新和重开可恢复。已有复制/文本及 DOCX 导出继续使用保存内容与 P2 完整性校验，不把机器提示当作人工确认或专业合格证明。

独立的模型辅助解释保持禁用：本轮不请求解释 API，不生成看似专业的合同释义或投资结论。术语备注只是用户输入或标明的示例，不能包装成专业审阅意见。
