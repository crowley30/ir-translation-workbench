# P3：有边界的已保存文本检查规则

`shared/review.ts` 的 `analyzeReview(task, resolvedByParagraph)` 是纯函数，只读已保存的原文、译文、段落 revision 和当前术语快照 ID。它返回可解释的核对提示，不修改译文，不确认审阅，不给质量分，也不表示合同、财务或专业翻译准确性通过。实际执行结果与完整阶段验收由本轮 verification 记录，不以本文件替代。

## 提示及定位

每条提示包含稳定段落 ID、DOCX 单元格/段落位置（文本任务则为段落序号）、规则代码、中文原因、原文和译文的精确片段。片段 start/end 是 JavaScript UTF-16 偏移，可直接用于 `slice(start, end)`；某侧没有可识别对应项时为 null，不猜测位置。片段至多 240 个 UTF-16 单元，不截断代理对；较长片段或段落概览仅提供开头摘录，不代表只需核对摘录，完整段落仍由段落 ID/位置定位。提示 ID 包含已保存段落 revision 和术语快照 ID；保存/快照变化后应重新分析。算法本身不更改人工审阅记录。

全部提示的 severity 为 `review`。`certainty=rule` 仅表示符合下述显式字符串/单位规则；`uncertain` 表示格式或语境需要人判断。它们都不是事实错误的最终判定。一个段落最多显示 80 条常规提示，达到该数目时追加明确的完整人工核对提示，不把限量显示伪装为检查完成。

## 数字、币种、日期和比率

| 项目                       | 本期自动识别的明确写法                                                                        | 等值或需要核对的例子                                             |
| -------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 数字                       | 阿拉伯数字、正负号、`.` 小数、合法三位逗号分组；至多 64 字符                                  | `1,200` 与 `1200` 等值；`12` 与 `13` 提示核对                    |
| 数量级                     | `hundred/thousand/million/billion/trillion`、`百/千/万/亿`；十进制字符串精确缩放              | `USD 12 million` 与 `1,200万美元` 等值，不依赖浮点近似           |
| 币种                       | USD/US$/美元，RMB/CNY/人民币，EUR/欧元、GBP/英镑、JPY/日元                                    | 同额美元与人民币提示币种核对；不做汇率换算                       |
| 日期                       | 年份 1900–2199 的有效 `YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY年M月D日`，完整英文月份的月日年/日月年 | `2026-10-26` 与 `2026年10月26日` 等值；日/月顺序有歧义时不猜地区 |
| 百分比、百分点、倍数、比率 | `%/％/percent/per cent`；`percentage point(s)/个百分点`；`x/倍`；`3:1/3：1/3比1`              | 百分比和百分点分开；不擅自把 `0.12` 等同 `12%`；不约分或倒转比例 |

币种符号 `$`、`¥`、`￥`、无明确人民币上下文的 `元`，以及中文数字、`百分之十二`、科学计数法、地区小数写法、省略整数位的小数（`.5`、`-.5`）、括号内的数值或金额（`(12)`、`（12）`、`(USD 12 million)`），给出 `UNCERTAIN_FORMAT`。括号可能表示会计负数或普通注释，本期不猜测；省略整数位的小数不会被拆成整数。这类写法不被猜成确定的数值不一致；相关未能匹配的项目也要求人工判断。`2026-02-29` 等无效日期同样不能作为有效日期进行等值判断。

检查采用分类和规范值的**多重集**，保留重复出现次数，可提示缺失、新增和不同值。它不能证明相同数字分别绑定了正确指标，也不能发现所有单位变更、倒装、否定、舍入、范围、注释或上下文语义。多个相同数字交换到不同业务对象仍可能没有提示；请逐段核对原译。

## 段落覆盖与模拟标识

- 非空原文而已保存译文为空时提示 `EMPTY_TRANSLATION`；源结构中的空段落不作为遗漏。
- 原文含较多内容（去空白、标点和符号后至少 120 个字符）而译文不足 12 个字符时，提示 `POSSIBLE_OMISSION`。这是低置信度长度启发式，不判断翻译完整性。
- 已保存内容等同英文原文时，同样只提示可能尚未翻译；专名原样保留可能合理。
- 只要实际内容含 `[模拟占位·非译文]`，提示 `MOCK_OUTPUT`，不继续用原文回显制造检查通过的印象。术语配置冲突不依赖译文质量，仍显示 `TERM_CONFLICT`；占位内容不参与缺少译词或数值一致性判断。mock 任务中人工保存的中文仍按规则检查；页面应继续明确其模型模式，不能据此声称真实模型或专业质量验收。

## 术语一致性

此模块消费术语解析器已计算的 `TermResolution`，不再自行对原文做短词扫描，不改变项目/基金/技术层级、优先级、大小写、缩写边界或长短词裁决。已解决的匹配按声明的目标、允许变体，以及明确配置的原文保留检查译文。英文目标的词边界不把 `AI` 误认成 `TAIL`、`éAI` 等词中的子串；Unicode 字母、组合标记、数字和下划线均参与边界判断，汉字邻接例外以允许「采用AI技术」等常见写法。大小写按术语设置处理；命中仍不保证该语境应保留缩写。

同一原文位置有多个共同胜出且选择相同的条目时，检查采用这些条目允许变体的并集；不会因采用其中一条允许的写法而给另一条重复报警。解析结果、术语条目、原文和各条备注均保持不变。所有候选都未出现时，只提示一条 `TERM_MISMATCH`，显示相关原文位置及全部共同胜出条目的备注，并明确语境/改写也可能合理，不自动替换。未解决的候选冲突提示 `TERM_CONFLICT`，不擅自选词。提示不是术语事实权威，允许变体也不代表任意上下文都应机械采用。

本模块不调用模型或任何外部服务，不读取密钥、不记录用户材料。测试均为合成句子；无真实 API 或专业质量验收。
