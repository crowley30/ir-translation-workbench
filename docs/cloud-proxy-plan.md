# Cloud 代理传输阶段计划

日期：2026-10-29。分支 `feat/cloud-proxy-transport` 从 `6c3db129179604b0469848252db4d8045af5fe44` 建立，后续 Draft PR 依赖 PR #3；不修改正在独立验收的 PR #3 head。本阶段只补齐 Cloud 代理传输及必要配置、状态和测试，不扩展翻译功能、预算轮次管理、部署或专业质量承诺。

## 目标与门禁

在原有服务端直连传输之外，增加明确选择的 Cloud 代理路径。采用精确锁定的 `undici@8.12.3` 显式 `ProxyAgent`，不修改全局 dispatcher，不使用可因 `NO_PROXY` 自动绕过的环境代理选择器。代理地址和信任配置仅来自受控服务端运行时配置，网页不能提交代理地址、CA 或秘密。

服务启动、读取状态、保存设置及启用控制仍不连接模型。操作员开关默认关闭、操作员预算默认 0；所有 PR #3 的密钥引用、模型目录、两项用户确认、段落 ID、人工修订保护、错误与累计费用预留规则保留。首次后续真实试跑的累计预算已确认 1 美元，含所有请求及重试；本轮仍不配置真实密钥、不读取真实 `OPENAI_API_KEY`、不发送真实认证或模型请求。

## 服务端配置契约

| 配置                                | 行为                                                                                                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TRANSLATION_TRANSPORT=direct`      | 显式使用原有直连及客户端 DNS/IP 固定，不因代理错误自动进入此模式。                                                                                                                                                        |
| `TRANSLATION_TRANSPORT=cloud-proxy` | 显式使用受控 Cloud HTTPS 代理；代理配置缺失或无效则阻止真实调用。                                                                                                                                                         |
| 未指定传输模式                      | 若已存在平台代理配置项，状态为未配置并失败关闭，避免误把占位符发往直连；仅在没有代理配置项时保留默认直连。                                                                                                                |
| `HTTPS_PROXY` / `https_proxy`       | Cloud 模式只从这两个服务端来源读取实际代理地址；两者冲突则拒绝。不会把 `HTTP_PROXY` 或猜测地址当作该模式的回退。                                                                                                          |
| `NO_PROXY` / `no_proxy`             | 不转交自动环境代理选择器，不允许其将固定目标绕过代理。                                                                                                                                                                    |
| CA 信任                             | 使用 Node 24.19 的 `tls.getCACertificates('default')` 取得实际默认信任，包含该进程启动时加载的额外根；按需将 `SSL_CERT_FILE` 指定的、最多 1 MiB 的 PEM 证书包追加。只接受证书，不接受私钥，不反射文件路径或原始读取错误。 |

`SSL_CERT_FILE` 的显式加载是本应用支持的服务端契约，不是官方 Cloud 文档承诺所有 Node 客户端自动读取该变量。代理地址、CA 文件内容及读取错误不得进入浏览器、数据库或日志；公开状态仅报告模式、就绪性、固定原因及 DNS 信任边界。平台实际代理与 CA 的非敏感契约会单独检查，但不读取或记录真实 API 密钥，不输出带凭据的代理 URL。

凭据头校验沿用当前 PR #3 的共享 Node 标准 `validateHeaderValue`：适配器在申请费用预留前拒绝非法头值，Cloud 传输在创建网络 agent 前再校验。不依靠自定义 ASCII 猜测，也不将非法值或原始校验异常写入响应、日志。该校验处理的是合成测试值或后续安全运行时值，本轮不读取真实凭据。

## 分阶段实施

| 步骤             | 实现与验收目标                                                                                                                                                                                                    |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 配置解析         | 明确区分直连和 Cloud 代理；缺失、冲突或不支持的配置失败关闭。只能使用平台实际提供的代理配置，不猜测地址，不将 TCP/VPN 文档中的地址硬编码为秘密替换代理。代理 URL 不得进入 API 响应、错误或日志。                  |
| 独立传输         | 目标固定为 `https://api.openai.com/v1/responses`，保留主机名用于 CONNECT、SNI 和 HTTP Host；禁止重定向、自定义目的地、环境绕过及直连回退。TLS 证书链和主机名均须验证，不能设置 `rejectUnauthorized:false`。       |
| 信任与资源       | 合并 Node 实际默认信任与受限公开 CA 包，保持 TLS 校验。使用显式 ProxyAgent 的有界 CONNECT 解析，CONNECT、TLS、响应头和正文均有取消、总期限、大小及清理界限；一次适配器尝试最多发送一个模型 POST，不叠加隐式重试。 |
| 本地真实协议测试 | 生成临时合成 CA/域名证书及 TLS 拦截假代理，实际走 CONNECT 和 TLS。只替换合成占位符，不访问任何外部上游；私钥只在临时目录中生成和清理，不提交。                                                                    |
| 集成与回归       | 覆盖默认关闭、配置状态、文本/DOCX、术语/数值提示、人工修改、取消、未知费用保留与并发预算；完整复跑既有 930 项 Vitest、10 项公开检查、61 项浏览器及本轮新增用例。实际数量、失败与退出码由最终执行记录填写。        |
| 交付             | 格式、lint、类型、测试、构建、浏览器和公开扫描，检查完整受控文件、提交差异、历史及客户端构建。推送独立分支、开依赖 PR #3 的 Draft PR，停待父任务验收；不合并、不部署。                                            |

## 代理的信任边界

| 路径       | 应用可以保证                                                                                     | 不应声称                                                               |
| ---------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| 直连       | 保留 PR #3 的全部 DNS 结果校验、连接 IP 固定、官方 TLS/SNI 与无重定向规则                        | 尚未实际执行的 Cloud 直连可达性、真实凭据认证或专业翻译质量            |
| Cloud 代理 | 官方目标和路径固定；只走受信任的平台代理；客户端验证对应的 TLS 主机与 CA；拒绝绕过、回退和重定向 | 客户端固定了代理最终连接的上游 IP，或本地 DNS 预检查等于代理侧连接固定 |

代理模式由平台代理解析/访问上游并可能执行 TLS 拦截和占位符替换。平台的允许域、解析与受保护地址约束属于明确的外部信任边界，不是应用可以从一次本地解析推导的事实。当前公开文档没有完整披露 HTTPS 代理的固定地址、CA 路径或上游解析实现；实际网络策略和秘密替换仍需后续真机验证。不得为使测试通过而放宽全局私网规则、关闭 TLS 或允许任意自定义目的地。

## 本地合成验收矩阵

- 成功：CONNECT 目标精确为 `api.openai.com:443`，TLS 主机名有效，合成占位符在假代理中替换，返回完整 Responses 结果且稳定 ID 一致；预算按既有规则预留/对账。
- TLS：不受信任 CA、错误主机名证书、错误代理证书均失败；不会切回直连。
- 代理：403/407、3xx、错误/超长 CONNECT 响应头、断开和无效配置均有界失败；不输出原始代理 URL、认证头或合成秘密。
- 资源：慢 CONNECT、慢 TLS、慢响应头/正文、超限正文、取消及迟到响应都释放本地资源；不承诺远端未执行或不计费。
- 隔离：`NO_PROXY`、大小写冲突、前端额外字段和自定义目标不能绕过代理；每次重试独立计入累计预留，未知费用不释放。
- 回归：默认 mock 不自动发送；原文本和 DOCX 导入、术语快照、人工确认、编辑保存及最新保存导出保持。

以上是验收目标，不把测试存在、假代理通过或官方文档阅读等同实际 Cloud 已认证成功。

## 用户后续最小安全配合

应在实现通过独立验收后进行；本轮不要求用户发送密钥或猜填代理地址/CA。

1. 打开本项目 Cloud 环境配置的 **HTTP secrets → Manage**，或在 **Settings → Codex Cloud → Personal vault → Add** 中选择 **Network secret**。填写环境请求的同名 Key（可用 `OPENAI_API_KEY`），Value 只在该安全界面输入，允许目的域限定为 `api.openai.com`。若用 Personal vault，绑定本项目环境，并确认环境确实请求该 Key；不要另建同名普通变量覆盖它。
2. 核对本项目环境允许访问 `api.openai.com`。个人值不会自动加入网络允许域，不能仅因 Key 已保存就假定网络已放行。保存环境、Republish，并在更新后的新任务使用；旧任务保留原状态。
3. 应用网页只填写凭据变量引用并选择已核对模型；传输模式与实际代理/CA 由服务端受控配置，用户不在网页填写代理地址或证书。保持真实调用关闭。父任务明确放行实际试跑后，再按累计 1 美元开启相应操作员与用户门禁，先用合成小样本；不把赠金或邮件到期时间当费用保证。

普通 **Environment variable** 也是官方支持的运行时方案，但原值会交给任务程序，隔离性质与 Network secret 不同；不能静默替代推荐路径。实际入口与差异见 [官方核对依据](cloud-proxy-reference.md)。
