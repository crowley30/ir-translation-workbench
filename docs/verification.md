## 独立验收返工

父任务对 `6ef1e6a` 的独立验收发现三处原有覆盖遗漏：创建响应等待期间新增输入可能丢失；合法 JSON 截断/非成功模型结果被当作成功；配置恢复后旧错误仍残留。因此第一次交付不能视为独立验收通过。

### 修复与有效断言

- **R1**：创建期间锁定原文、文体与模拟场景，使用提交时的快照；失败保持原文并解锁。延迟成功和延迟 503 均以真实原生键盘尝试验证不可更改，断言创建次数及落盘原文。模式变更保留原文草稿和已创建任务，不自动翻译。
- **R2**：真实适配器只接受单个 `index=0` / `finish_reason=stop` / `role=assistant` 的完整输出，无拒绝和工具调用，并继续严格校验 JSON。截断、拒绝、缺失/未知完成状态均不保存为成功。注入 fetch 测试同时覆盖新任务失败和局部重译保留人工内容/版本，不调用真实 API。
- **R3**：配置、任务列表、任务读取及操作错误分别管理；对应读取恢复只清除对应提示。另补保存成功后列表读取失败的恢复测试，防止读错被永久归为操作失败。
- **R4**：公开检查覆盖 HEAD、完整 index、当前受审文件和指定基线以来逐提交变化的历史快照。暂存区为空也不跳过，扫描范围为空明确失败。8 个脚本测试验证这些行为。

回归有效性：在 `/tmp` 的隔离基线副本中仅覆盖新适配器及服务测试、保持 `6ef1e6a` 实现，运行 `npm test -- server/adapter.test.ts server/service.test.ts` 退出 `1`，44 失败、65 通过；旧实现确实会将截断/拒绝等错误结果标为完成。修复实现的相同范围及完整后端测试通过。
