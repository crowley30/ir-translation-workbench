# 橙橙的 IR 翻译工作台

面向科技基金 IR 的单人中文网页工具，优先支持桌面浏览器。当前轮次实现英文文本粘贴、逐段对照、人工编辑和服务端持久化；DOCX 与术语检查属于后续 V1 计划。

**默认是模拟模式。模拟结果是明确标记的占位内容，不是英文原文的中文翻译。** 本轮仅使用合成样本，没有调用收费 API，没有配置真实凭据；模拟验收不能证明真实 API 可用或专业翻译质量合格。

## 本地运行

需要 Node.js 24 或更高版本及 npm。应用使用 Node 自带的 SQLite，无需另装数据库。

```sh
npm ci
npm run dev
```

打开终端显示的 Vite 本地地址（通常为 `http://127.0.0.1:5173`）。前端通过 `/api` 代理访问 `127.0.0.1:3001` 的服务端。两个进程均用于本机使用，勿把端口公开。

构建并以单个服务端提供页面：

```sh
npm run build
npm start
```

打开 `http://127.0.0.1:3001`。

## 使用流程

1. 粘贴英文文本，用空行分段，选择「忠实合同」或「商务文体」后创建任务。单次最多 20,000 字符、100 段；空白文本不能提交。创建期间原文、文体和模拟选项暂时锁定，失败后原文保留且可重试；服务模式变更时保留草稿、列出已创建任务，并停止自动翻译。
2. 启动模拟翻译，查看原文与占位结果逐段对照。页面会显示运行状态、失败原因和模式标记。
3. 修改译文并保存。任务保存在服务端 SQLite；任务列表可重新打开，刷新页面后也可恢复已保存的内容。
4. 失败或取消后可以重试未完成段落。局部重译只更新选中段落；已有人工编辑默认受到保护。明确选中人工编辑段落重译会替换该段已保存内容，运行期间的新修改通过版本检查保护。
5. 复制或导出当前译文文本。导出供人工复核；模拟输出中保留模拟标记。

保存期间继续输入的草稿会保留；服务已有新版本时，需确认后才用人工草稿覆盖。保存失败时应先解决页面提示的错误再离开。刷新只能恢复已经成功写入服务端的内容，未保存输入不可视为已持久化。服务端重启会将中断的运行标为已取消，并允许手动重试，不会自动继续发出模型请求。配置、任务列表及任务详情的自动读取采用独立串行轮询：一次读取完成后再等待下次间隔，慢成功响应仍会生效；每次自动读取（含正文解析）最多等待 5 秒，超时取消后重试。切换任务或卸载会停止对应读取并忽略迟到响应。

## 数据与服务边界

- 单用户、本机运行，无登录或访问控制。本版本不适合公开部署；仓库公开不等于应用公开可用。
- 数据文件默认位于 `.data/workbench.sqlite`，可通过服务端 `DATABASE_PATH` 修改，已被 Git 忽略。请按敏感 IR 材料管理本机数据库与导出文件；当前数据库不提供应用级加密。
- 未配置模型服务时保持醒目的模拟模式，不把占位内容冒充实际翻译。真实适配器的配置与限制见 [架构与 V1 计划](docs/v1-plan.md#模式故障与保密)。密钥只允许在服务端环境变量中提供，禁止放入前端、日志或仓库。
- 仓库示例与测试均为合成内容。不要把真实邮件、基金信息、客户数据或凭据加入测试、截图、提交或 PR。
- 本轮未实现 DOCX、PDF、OCR、邮件账户接入、自动发送、多人协作、公开部署或复杂知识库。

## 检查命令

```sh
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

配置会优先使用已有的 `/usr/bin/chromium`，无系统浏览器时才需要执行下载命令。云端默认 npm 缓存不可写时，可使用 `npm_config_cache=/tmp/ir-npm-cache npm ci`。实际运行结果以 [本轮验收记录](docs/verification.md) 为准。未运行的检查必须记录为「未运行」。
